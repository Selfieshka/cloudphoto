# CLOUDPHOTO

## Требования к окружению

### Переменные окружения

Для Terraform:

| Переменная | Описание                      |
|---|-------------------------------|
| `YC_TOKEN` | токен доступа к  Yandex Cloud |

Для `cloudphoto`:

| Переменная | Описание                                |
|---|-----------------------------------------|
| `BUCKET` | Имя бакета Object Storage               |
| `AWS_ACCESS_KEY_ID` | Access key для доступа в Object Storage |
| `AWS_SECRET_ACCESS_KEY` | Secret key для доступа в Object Storage |

Указано напрямую в коде:

- Регион: `ru-central1`
- Endpoint: `https://storage.yandexcloud.net`  

## Развёртывание инфраструктуры

В каталоге `terraform` находится файл `main.tf`, который создаёт:

- сервисный аккаунт с ролью `storage.admin`
- статический ключ доступа для `cloudphoto`
- бакет с HTTPS-сертификатом из Certificate Manager
- Запись сайта в DNS-зоне

Входные переменные:

| Переменная | Значение |
|---|---|
| `folder_id` | ID каталога Yandex Cloud |
| `bucket_name` | Имя бакета, совпадает с доменом сайта и с `BUCKET`, например `photos.vvotNN.itiscl.ru` |
| `domain` | Доменное имя сайта, например `vvotNN.itiscl.ru` |
| `cert_id` | ID сертификата в Yandex Certificate Manager |
| `dns_zone_id` | ID DNS-зоны в Yandex Cloud DNS |

1. Переходим в директорию `terraform`
```bash
cd terraform
```
2. Создаем свой файл с секретными переменными из образца
```bash
cp terraform.tfvars.dist terraform.tfvars
```
3. Открываем созданный файл и вписываем значения вместо плейходеров
```bash
nano terraform.tfvars
```
4. Создаем переменную окржуения с токеном для YC
```bash
export YC_TOKEN=$(yc iam create-token)
```
5. Инициализиоруем проект с терраформом
```bash
terraform init
```
6. Выполняем файлы терраформа
```bash
terraform apply
```

7. Создаем переменные окружения, необходимые для работы приложения
```bash
export BUCKET=photos.vvotNN.itiscl.ru
export AWS_ACCESS_KEY_ID=$(terraform output -raw access_key)
export AWS_SECRET_ACCESS_KEY=$(terraform output -raw secret_key)
```

## Сборка приложения

1. Собираем программу в `build/install/cloudphoto/bin/cloudphoto`
```bash
./gradlew installDist
```

2. Добавляем путь к нашему приложению в PATH для удобства
```bash
export PATH="$PWD/build/install/cloudphoto/bin:$PATH"
```

## Схема организации облачного хранилища

```
index.html
error.html
album1.html … albumN.html
albums/<ALBUM>/.album
albums/<ALBUM>/<PHOTO>
```

| Ключ | Назначение                                                              |
|---|-------------------------------------------------------------------------|
| `albums/<ALBUM>/<PHOTO>` | Фотография: `<ALBUM>` это имя альбома, `<PHOTO>` это исходное имя файла |
| `albums/<ALBUM>/.album` | Служебный пустой объект, обозначающий существование альбома             |
| `index.html`, `error.html`, `album{N}.html` | Страницы сайта, создаваемые командой `mksite`                           |

### Пояснения

1. Все фотографии и служебные объекты альбомов лежат под префиксом `albums/`, а страницы сайта в корне бакета. Ключи страниц не начинаются с `albums/`, поэтому они не пересекаются с фотографиями при любом имени альбома
2. Альбом существует, если в бакете есть хотя бы один объект с префиксом `albums/<ALBUM>/`. Список альбомов получается запросом с префиксом `albums/` и разделителем `/`
3. Комманда `upload` при отправке фотографий всегда записывает служебный объект `albums/<ALBUM>/.album`. После удаления всех фотографий через `delete --photo` маркер остаётся, и альбом продолжает существовать как пустой. `delete` без `--photo` удаляет все объекты альбома вместе со служебным объектом
4. Т.к. фотографией считается только файл, имя которого без учёта регистра оканчивается на `.jpg` или `.jpeg`, значит имя `.album` под это правило не подходит, следовательно фотографии с таким именем быть не может и ое не выводится в списке фотографий и не может быть удалён через опцию `--photo`
5. Ключ `albums/<ALBUM>/<PHOTO>` однозначно определяет альбом и исходное имя файла
6. Повторный вызов `upload` файла с тем же именем в тот же альбом записывает объект с тем же ключом, то есть заменяет фотографию.
7. Повторный вызов `mksite` перезаписывает страницы сайта
8. Имена альбомов и исходные имена файлов используются в ключах без изменений. Символ `/` в имени альбома запрещён, если его ввести, то программа завершится с ошибкой
